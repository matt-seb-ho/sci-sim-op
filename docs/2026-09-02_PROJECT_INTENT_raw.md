The overall goal is to do research on AI4S (AI for science). And the niche we've picked is trying to get agents to be better at operating scientific simulators. We're also interested in increasing the scope to the broader workflow that includes operating the simulator. This workflow obviously varies in disciplines and on the project, but we basically want agents to be able to handle more of the busy work that scientists do. For obvious reasons: accelerating scientific progress because these things should be more parallelizable/work harder than people who need sleep and breaks. In a more human friendly framing, how to reallocate valuable researcher time towards higher level planning and thinking instead of working on low level details.

We don't have a huge or really much GPU budget at all so training is almost completely off the table. So that leaves harness optimization which costs inference instead which is more stomachable. We're interested in a system that self improves. We're interested in making systems maximally useful to actual scientists.

Regarding methodology, our adapter idea is not something we're overly attached to. What we discovered early on was that our agent harness we implemented from scratch underperformed a very polished piece of software, the Claude Code harness which has some of the brightest, well compensated researchers and engineers at Anthropic who seems to be leading the race right now working on it. So out of necessity more than anything we decided ok then our improvements must sit on top of this as an adapter. Actually this happens to be fairly appropriate place to land because when we first set out, our goal was "how do you do domain adaptation" of LLM coding agents which are usually more optimized for generic SWE tasks to work on extremely domain specific work (such as niche scientific things like geoscience simulation).

So our research started on "how do you do domain adaptation" which I think is related to the Jacob Li blog post about machine studying. I came up with a similar formulation before his post released in consideration for this follow up project to our initial SIGA work. The point is that this simulator is an elaborate piece of software but the documentation on it is actually quite solid. But the documentation likely doesn't all fit into context at once and doing so is likely an inefficient way of processing it. So the metaphor we give is an open book test. You have the textbook so you can find the answer given enough time in the test, but what studying gets you is not perfect memorization of the textbook but your studying forms understanding that lets you have better navigate the textbook more efficiency. You understand the structure of the textbook, you know what you're looking for, you know what to search for, etc. So a related work is https://arxiv.org/abs/2605.19932 (add this to the literature search). But we want to apply this idea to not just a single source like documentation but depending on the task there might be multiple resources like papers, books, blogs, etc. that you need to aggregate. And some things you might internalize besides factual knowledge is procedural know-how like how to handle various situations, how to find relevant/useful info more efficiently.

So in conclusion we have a pretty wide goal of "making agents better for scientific research tasks, particularly centered around simulation". Our initial method SIGA was a lightweight adapter that was born out of resource scarcity and empirical results that models are optimized around coding harnesses and a small idea that having a small search space of modules makes exhaustive search of optimal combinations is doable but I think the field is tending towards using LLM as the driver to identify problems/weaknesses and to propose and implement improvements to the system.

Anyways we want to think about ideas around (1) being better at the open book exam (2) self evolution/self improving systems and (3) doing harness/system optimization due to the same lack of resources.

So methods wise we have pretty free reign. Some things we've been thinking about as explicit follow up work from the SIGA paper:
1. expanding scope (increasing depth of domains) of the task (we started pretty narrow, presuming that the user provides the entire spec but not in the simulator DSL; a narrow translation task from a code book/dictionary that is the docs) but we want to expand the responsibility of what the agent does. So one light way to do this is to try to mask the inferable parameters of a spec (allow for partial spec as input) which we started investigating. But the better way to do this is to talk with actual domain experts and researchers in each target domain and find out what the actual workflows look like so we can build benchmarks and methods around those. I'll put it on my personal TODO list to schedule meeting with our domain collaborators
2. expanding the breadth of domains: study other simulators and domains (we currently have GEOS, OpenFOAM, and LAMMPS considered; geoscience, fluid dynamics, molecular dynamics)
3. improving the self evolution method. Our SIGA effort in this dimension is *extremely* rudimentary and broken in many ways. There has been a lot of work in this direction over the past few months (which you've already done literature search/review on for me). The TODO around this is to re-implement and test various new techniques for self evolution/self improvement methods to see what's effective and maybe adopt and combine ideas across papers, etc. But the first step is obvious: figure out what exists, make a list of things we want to try, implement, then test these things.

The last piece of relevant context is that the funding for this project is attached to a UC collaboration (helmed by UC Irvine) centered around Geoscience + AI. There are various subgroups working on this. Some folks are working on PINNs, some folks are working on training models on multimodal data, our team is in charge of LLM agents. So my personal feeling is that I have no interest in geoscience. I'm sure their work is important but I don't find the subject interesting the same way I find biology/medicine/physics/chemistry interesting. However because of grant stipulations we necessarily need to work on geoscience applications. This also implies that we have most access to domain experts for geoscience specifically (geoscience researchers at UCI and at LLNL). As an AI researcher and as someone who cares deeply about AI for Science, I don't want to tie our researcher too closely to geoscience. I think we should demonstrate efficacy across several domains and geoscience can be the first and main one because of expert access,  but ideally we develop general methods of domain adaptation and self improvement and efficient study that can be readily used on various scientific disciplines.
